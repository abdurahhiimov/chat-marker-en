Chat Marker — how it all works

Version 1.1 · marker in the browser, library in Google Drive, access from Claude.

What it is and what for

Chat Marker is a marker that works on any web page: in a chat with Claude, in an article, in documentation. You highlight a chunk of text, hang a topic on it — and it stays yours. Not in the clipboard, but in a database the library later gets built from.

The tool is made of three parts, and it matters that you get this, because everything below is explained through them:

  • The browser script — the thing that draws the marker and stores the highlights. It lives in Tampermonkey.
  • The library builder — a Python script on the Mac. It turns raw highlights into folders, files and a dashboard.
  • The MCP server — a little bridge to Claude Desktop. Through it Claude searches and reads your highlights.

How the information flows

The most common confusion is where things show up and at what moment. Here is the whole path of one highlight:

1You highlight it on the pageThe chunk gets painted in the topic's color. It sits in the browser, in the Tampermonkey database.
2You press "Export to library"The browser downloads the highlights file into Downloads. This is the only manual action.
3The file moves to the InboxThe agent on the Mac moves it into the 00 Inbox folder. Claude does the same on any request to the highlights.
4The builder rebuilds everythingTopics, pages, index, spreadsheet, dashboard, documents for the marked topics.
5Google Drive syncs itThe folder goes up to the cloud — available from your phone and from another computer.
6Claude reads it over MCPSearch, topics, sequence, a summary — right there in the chat.
The main rule: until you press "Export to library", nothing new shows up in Google Drive. The browser is the working buffer, Drive is the archive.

Installing from scratch

On a clean Mac. You need nothing up front — no Python, no Homebrew, no admin password.

1. One command in Terminal

Cmd+Space → "Terminal" → paste the whole thing:

curl -fsSL https://raw.githubusercontent.com/abdurahhiimov/chat-marker-en/main/install.sh | bash

The installer finds Python itself or downloads its own into ~/.chatmarker, finds Google Drive (and if there isn't one — puts the library into "Documents"), creates the folder structure, registers the MCP server in Claude Desktop if that's installed, and hangs a background agent. Running it again is safe — that's also how you update.

2. The browser extension

Tampermonkey from tampermonkey.net → the Chrome button → Install.

Next comes a mandatory step, without which the extension silently does nothing: right-click the Tampermonkey icon → "Manage extension" → turn on Allow User Scripts. On Chrome older than 138 there is no such toggle — then it's chrome://extensions → top right corner → Developer mode.

3. The script itself

Open it in the browser — Tampermonkey intercepts the link and shows an Install button:

https://raw.githubusercontent.com/abdurahhiimov/chat-marker-en/main/chat-marker.user.js

That's also how it updates itself later: the script has an update address in it, and Tampermonkey checks it periodically. By hand — the same link once more.

4. Restarting Claude Desktop

Cmd+Q and open it again. Just closing the window isn't enough: MCP servers are only picked up at startup.

If you don't want the terminal

The first two points are enough for the marker to work: highlights, topics, colors, the panel and the export live entirely in the browser. To look at what you've piled up, use the Highlights Viewer.html file — it opens on a double click, takes highlights.json by drag-and-drop and requires nothing at all.

Highlighting and topics

You select text with the mouse and a little panel appears. What's in it:

ElementWhat it does
The yellow "Highlight" buttonSave with no topic. Yellow is reserved for "no topic" — you see yellow, it means it hasn't been sorted out.
Two topics next to itThe ones you used last. Click and the highlight is painted in the topic's color.
⋯All the other topics as a list, with search.
The little colored squareThe palette. The color is the fill of the highlight, and also the topic's color.
B / U / SBold, underline, strikethrough. They can be combined. There is no italic — the browser can't slant text in this highlighting mode.
+A new topic right here: name, color, save. No extra windows.
The red deleteShows up when you select an already marked chunk — removes the highlight.

Removing part of a highlight

If you select the middle of an already marked chunk and press delete, only the middle goes — the edges stay as two separate highlights. That's how you trim badly grabbed text without redoing the whole thing.

Why the highlighting doesn't fall off

The highlight is drawn on top of the page, not inserted into it. So the chat can keep writing out its answer, the page can repaint completely — the marks stay put. For the same reason they don't break the layout and don't get in the way of copying text.

The side panel

Opens with Alt+H or by clicking the round button in the corner.

  • Search — across the highlight text, the note and the page title.
  • Everywhere / This page — show everything or only what was marked here.
  • Topics — clicking a topic toggles the filter, the check mark on the right pins it. Pinned ones add up: you can look at two topics together.
  • to the spot — scrolls the page to the highlight, if you're on that page right now.
  • source ↗ — opens the original page and scrolls to the right paragraph on its own.
  • note — your own thought next to the quote. It's the notes that make the summary useful later.

At the bottom are the actions: export to the library, pasting into the chat input, copying as Markdown, import, buffer size.

The buffer. The browser keeps up to 10,000 highlights. When there are more, the oldest get evicted — but only the ones that already left for the library. Anything not exported is never touched.

Topics: the live document and deletion

The ⋯ button in the panel opens the full list of topics. There, each topic has two buttons.

The document icon

You mark a topic — and on every export <topic>.docx gets rebuilt in the 06 Documents folder. You can mark as many topics as you like, but it only makes sense for two or three you're actually working on.

The trash can

The row turns into a question. "Drop the topic" — the highlights stay, they move to "no topic" and show up in the 03 No topic folder. The red "and N of them" — the topic is deleted together with the highlights, for good. ✕ — cancel.

The changes show up in the library after the next export — until then Drive is showing the old picture.

Export to the library

The "Export to library" button downloads the highlights.json file with all the highlights and topics into the Downloads folder. Since version 1.2 the export also happens by itself: once every 10 minutes, if there's anything not exported (the counter in the panel shows how much, clicking it exports right away). From there the file gets into the library by two routes, and both work on their own:

  • The agent on the Mac — watches Downloads and moves the file into 00 Inbox.
  • Claude — before any request to the highlights it picks up the fresh file itself and rebuilds the library.

If you want it by hand, right now:

~/.chatmarker/venv/bin/python ~/.chatmarker/library.py --force

The --force flag rebuilds everything, even if nothing changed. Useful after updating the tool.

Exports merge, they don't overwrite. You can export from two computers — the library will put it all together. Delete a highlight or a topic in the browser and after the export it gets deleted from the library too; but old stuff that's already been evicted from the browser buffer stays in the library forever. Previous versions are in 09 Archive/backups (the last 30).

The Google Drive folder

AI Highlights/
├── 00 Inbox/          raw material: highlights.json. The single source of truth
├── 01 Topics/         one file per topic
├── 02 Pages/          one file per source
├── 03 No topic/       what you saved without picking a topic
├── 04 Drafts/         your territory, the builder doesn't go in here
├── 06 Documents/      a live .docx for every marked topic
├── 09 Archive/backups/  the last 30 versions of the export
├── Index.md           numbers, topics, sources, what's recent
├── Highlights.xlsx    a spreadsheet with filters, opens in Google Sheets
└── Dashboard.html     the feed of highlights, buttons for Claude

Everything except 04 Drafts is rebuilt from scratch on every export. Edits in generated files get wiped — write your own thoughts into the drafts.

A single highlight lands in several places at once: in its topic, in its page, in the spreadsheet. These aren't copies in the messy sense, they're different ways of looking at the same Inbox.

Dashboard

You have to open it locally. The dashboard is an HTML file. In the drive.google.com web interface it doesn't run: the browser shows it as a file, not as a page. Open it through Finder: Google Drive → AI Highlights → Dashboard.html, double click. Then both the filters and all three buttons work.

On large volumes the dashboard shows the first 400 cards and a "Show more" button — that way it opens instantly even at ten thousand highlights.

The point of the dashboard is the sequence. Not "all the quotes in a pile", but the order you found them in, broken into sittings: a break longer than half an hour starts a new block with a date and time.

Documents: the live .docx and Google Doc

There are two different mechanisms here, and they're easy to mix up.

1. The live document — made by the builder

Mark a topic with the document icon and on every export <topic>.docx appears in 06 Documents. The file is overwritten whole, so the link to it doesn't change: you can hand it to a colleague once, and they'll always see the fresh version.

It's an ordinary .docx inside the Google Drive folder. A double click in the Drive web interface opens it in Google Docs. It doesn't become a native Google document from that — it's a Word file that Google can show and edit (on editing, Google will offer to make a copy, and that copy will be a native Google Doc — but it will stop updating).

Turn the icon off and the topic's file is deleted at the next build. The builder doesn't touch anything else in the folder: your own files there are safe.

2. A one-off summary — made by Claude

The "Ask Claude to work through it" button in the dashboard opens Claude Desktop with the task already written: take the topic over MCP, work through it by meaning and put the finished document into Google Drive through the connector. This is where you get a real Google Doc — it's created by Claude, not by the builder.

What you need for that:

  • Claude Desktop is running and the highlights MCP server is connected;
  • the Google Drive connector is on in Claude (in settings, the connectors section) — otherwise it will put the analysis together right in the chat but won't create a file in Drive;
  • the dashboard is opened locally, not on the web — a claude:// link from the web preview won't work.

The difference is simple: the live .docx is your quotes, as they are, always fresh. The Google Doc from Claude is the analysis: a coherent picture, the contradictions, what's missing. The first happens by itself and for free, the second is for when you need to think.

Claude and MCP

The MCP server is called highlights. It gives Claude access to your library — no copy-pasting into the chat needed. Before every request it picks up the fresh export from Downloads itself and rebuilds the library.

The sequence for a topic"Show me how I moved through the unit economics topic"

In the list of topics, the ones with a live document are marked with an icon — that way you can see what's already automated.

If something is off

The marker doesn't appear

Check that the script is enabled in Tampermonkey, and that in chrome://extensions Tampermonkey has Allow User Scripts set. Reload the tab — the script hooks in when the page loads.

Nothing changes in Drive

Most likely the export wasn't pressed. If it was — rebuild by hand:

~/.chatmarker/venv/bin/python ~/.chatmarker/library.py --force

The dashboard looks the same as before

Same case: the dashboard is rebuilt together with the library. And open it from Finder, not from the Drive web interface.

Claude doesn't see the new highlights

Restart Claude Desktop with Cmd+Q. It keeps the MCP server's code in memory and after an update keeps running the old one.

The "Ask Claude to work through it" button doesn't open anything

The dashboard is open in web Drive, not locally. claude:// links only work from a real page in the browser.

There is no .docx

Check that the topic is marked with the document icon and that there was an export after that. If instead of a .docx there's an .md lying there — a library is missing:

~/.chatmarker/venv/bin/pip install python-docx
